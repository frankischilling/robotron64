# Audio bus mixing, resampling and stereo output

The main bus, auxiliary bus, resampler and save filter reconstruct eight
complete target procedures totaling 1,548 code bytes. The filter constructors and synthesizer
connect these procedures through the shared callback declarations in
`sdk_audio_pipeline.h`.

| Source | Target code range | Procedures | Live bytes |
| --- | --- | ---: | ---: |
| `src/sdk/audio_main_bus.c` | `0x8006BE20..0x8006BF70` | 2 | 336 |
| `src/sdk/audio_resample.c` | `0x8006CAC0..0x8006CDB4` | 2 | 756 |
| `src/sdk/audio_auxiliary_bus.c` | `0x8006DA20..0x8006DB28` | 2 | 264 |
| `src/sdk/audio_save_filter.c` | `0x8006DB30..0x8006DBF0` | 2 | 192 |

Both buses clear their left and right output buffers before invoking each
registered source in order. The main bus mixes the auxiliary outputs into
its own outputs after each callback, using a gain of `0x7FFF`. The auxiliary
bus leaves that mixing to its downstream consumer. A bus callback can update
the source count: the loop reloads the count after each call, while retaining
the original source-array pointer.

The add-source parameter writes a pointer at the current source count and
then increments the count. The target does not check the recorded capacity.
Unsupported parameter identifiers return zero without modifying the bus.

The save filter first asks its source to generate audio, then emits buffer,
interleave, buffer and save commands. The first buffer length is twice the
sample count; the interleaved stereo length is four times the count. Its
parameter handler accepts a source pointer or a DRAM output address and
ignores other identifiers. The source callback must be present when output
is requested, as in the target.

## Command words and memory layout

The command macros in `sdk_audio_mix_commands.h` build on the packet cursor
definition in `sdk_audio_commands.h`. They construct eight-byte packets and
evaluate a command cursor once, including post-increment expressions. They
preserve the target field masks and shifts. Buffer commands keep the low
16 bits of the byte count; clear commands retain the complete count word.

| Buffer | RSP DMEM address |
| --- | ---: |
| Decoder output | `0x0140` |
| Main left | `0x0440` |
| Main right | `0x0580` |
| Auxiliary left | `0x06C0` |
| Auxiliary right | `0x0800` |

The target command words establish these addresses and the packet layout.
The pinned `decompals/ultralib` files `src/audio/mainbus.c`, `auxbus.c` and
`save.c`, together with `resample.c`, supplied comparisons for the filter
interfaces and command meanings;
their revision and project credit are recorded in [CREDITS.md](../CREDITS.md).
The distributed procedures were reconstructed against Robotron's verified
instruction records. The reference checkout remains a separate research input.

## Resampling and pitch control

The resampler returns the input command cursor unchanged for a zero-length
request. Unity-pitch mode asks its source for the requested number of samples
and emits a DMEM move. Otherwise it clamps the stored ratio to `1.99996`,
quantizes it to increments of `1 / 32768`, and combines the requested sample
count with the retained fractional remainder. The resulting integer count is
passed to the source, and the fractional part is retained for the next call.

The target compares the ratio with a double-precision constant and stores a
single-precision clamp value. Preserving the literal `1.99996` reproduces both
constants. The output path emits buffer and resample commands using the
physical address returned by `func_800606A0`, then clears the first-block flag.

The parameter handler installs a source, resets motion and fractional state,
starts playback, changes pitch through the original integer/float bit union,
or enables unity-pitch mode. Reset and start propagate to the source when it
is present. Other parameter identifiers are forwarded unchanged.

## Matching evidence

IDO 5.3 with `sdk-o3-mips2-r4300-mul` reproduces every live byte and each
procedure's actual object offset and size. The parameter handlers occupy
object offset zero; the main-bus, auxiliary-bus, save and resampler processing
handlers begin at `0x30`, `0x30`, `0x34` and `0xEC`, respectively. None of
these objects emits writable initialized data or BSS.

The resampler owns 52 bytes of `.rodata` at `0x80095F00..0x80095F34`, ROM
`0x96B00..0x96B34`. The nine-entry parameter jump table is followed by four
alignment bytes, the double clamp constant and the float clamp constant.
Every generated byte matches the target. The constant-section tail and the
12 trailing code alignment bytes are validated before trimming; the live
procedure counts exclude the trailing code padding.

The auxiliary bus has eight natural trailing alignment bytes after its
264-byte live extent. The padding verifier checks those bytes before trimming
them; they are excluded from the source-function count and byte total. The
canonical comparison registry covers each complete unit, and the linker
places its verified code at the ranges above. The production input ledger
records source, transitive header and compiler identities.
