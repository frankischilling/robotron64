# Error formatters

The fatal formatter at `0x8001C0D0..0x8001C2C4` occupies 500 instruction
bytes. The warning formatter at `0x8001C2C4..0x8001C49C` occupies 472.
Both use a 500-byte message buffer and read integer and pointer varargs
from the o32 argument homes. They recognize `%C`, `%c`, `%d`, `%s` and
`%x`. An unrecognized percent specifier consumes the specifier without
advancing the argument cursor. Character arguments use the last byte of
the four-byte home. This is static evidence from retail MIPS, not a
complete execution proof or a claim that either formatter matches C.

`src/game/diagnostics/messages.c` reconstructs the 64 initialized bytes
at `0x80090420..0x80090460`, including the four diagnostic strings,
terminators and zero padding. The fatal path passes the format string,
message buffer, source filename and line 77 to the renderer diagnostic
service. The warning path submits its prefix and message separately.
The strings' addresses and complete bytes were checked through the saved
`robotron64.elf` Ghidra analysis and the target ROM.

A fresh pinned IDO comparison verifies the complete section, every
symbol's offset and size, and all 64 retail bytes. A separate reference
generated by splat/spimdisasm reassembles to the same bytes. Its four
symbols and complete `.rodata` section each match the canonical source
object at 100% in objdiff. IDO emits 62 raw section bytes; the existing
owned-section normalizer preserves the final two zero alignment bytes.
Neither formatter contributes instruction ownership or matching-function
progress. Their candidates remain private and are tracked in
[issue #103](https://github.com/frankischilling/robotron64/issues/103).

The accompanying actor research retains the excluded boundary clamp's
two spill-slot differences at `0x80018590` and `0x80018594`. Independent
splat/spimdisasm reassembly matches all 600 retail bytes. Complete source
comparisons still reject it. The audio timing callback similarly retains
four instruction differences in its complete 132-byte comparison; its
independently assembled reference matches the full retail range. The
targeted permuter run included stack offsets and produced no accepted
function. Its best candidates remain private. [Issue #94](https://github.com/frankischilling/robotron64/issues/94)
tracks the boundary clamp.

The diagnostic analysis uses Ghidra MCP, splat, spimdisasm and m2c with
the pinned IDO context. The local SM64 and libreultra stdarg headers were
consulted to check big-endian argument-home access. No reference header
or extracted assembly is added to the public source. Tool and reference
attributions remain in [CREDITS.md](../CREDITS.md).

## Validation

Fresh independent comparisons pass for 870 runtime units, two startup
units, 18 assembly units and 104 initialized-data/BSS units. A separate
clean source directory passes setup, build and full-ROM verification.
All 155 tooling tests pass. The rebuilt 8,388,608-byte ROM has SHA-256
`91d85baeca4b9517e93b3637b52909cee942b09e2fe44a37df9ded17687faddd`.
The [provenance ledger](error-formatters-provenance.json) records the
comparison and toolchain identities.

This change adds 64 initialized source-owned bytes and no instructions
or matching C functions. Totals remain 1,388 matching C functions and
277,596 C bytes; initialized-data ownership rises to 30,731 bytes.
Fallback code and data still prevent source-completion claims.
